# DocExtractor 文档信息提取系统 - 故障排查指南

## 🔍 故障排查流程

```
1. 确定问题类型
   ↓
2. 查看错误信息
   ↓
3. 按本指南排查
   ↓
4. 尝试解决方案
   ↓
5. 验证是否解决
```

---

- Excel 生成失败

## 🚨 启动问题

### 问题 1：ModuleNotFoundError

**错误信息：**
```
ModuleNotFoundError: No module named 'xxx'
```

**原因：** 缺少 Python 依赖包

**解决方案：**
```bash
# 安装缺失的包
pip install xxx

# 或重新安装所有依赖
pip install paddlepaddle-gpu paddleocr ollama tqdm openpyxl pyyaml pandas
```

---

### 问题 2：配置文件加载失败

**错误信息：**
```
✗ 配置文件加载失败: Expecting property name enclosed in double quotes
```

**原因：** JSON 格式错误

**解决方案：**

**步骤 1：验证 JSON 格式**
```bash
python -m json.tool config.json
```

**步骤 2：常见错误**
```json
// ❌ 错误：最后一个元素后有逗号
{
  "device": "gpu:0",
}

// ✓ 正确
{
  "device": "gpu:0"
}

// ❌ 错误：使用单引号
{
  'device': 'gpu:0'
}

// ✓ 正确：使用双引号
{
  "device": "gpu:0"
}
```

**步骤 3：恢复默认配置**
```bash
cp config.example.json config.json
```

---

### 问题 3：模板文件无效

**错误信息：**
```
✗ 模板文件无效: Template missing required keys: ['fields']
```

**原因：** 模板文件缺少必需字段

**解决方案：**

检查模板是否包含必需字段：
- `name`
- `display_name`
- `fields`
- `output`

参考 `templates/hukou_register.json` 的格式。

## 🔌 连接问题

### 问题 4：Ollama 连接失败

**错误信息：**
```
✗ Ollama 连接失败:
  无法连接到 Ollama 服务 (http://localhost:11434)
```

**排查步骤：**

**步骤 1：检查 Ollama 是否运行**
```bash
# Windows
tasklist | findstr ollama

# Linux
ps aux | grep ollama
```

**步骤 2：启动 Ollama**
```bash
ollama serve
```

**步骤 3：测试连接**
```bash
curl http://localhost:11434/api/tags
```

**步骤 4：检查端口占用**
```bash
# Windows
netstat -ano | findstr 11434

# Linux
netstat -tulpn | grep 11434
```

**步骤 5：检查防火墙**
- 确保端口 11434 未被防火墙阻止

---

### 问题 5：模型不存在

**错误信息：**
```
✗ Ollama 连接失败:
  模型 'deepseek-r1:32b' 不存在
```

**解决方案：**

**步骤 1：查看已安装的模型**
```bash
ollama list
```

**步骤 2：拉取模型**
```bash
ollama pull deepseek-r1:32b
```

**步骤 3：验证模型**
```bash
ollama list | grep deepseek
```

---

### 问题 6：OCR 模型加载失败

**错误信息：**
```
✗ 模型加载失败: 未找到以下OCR模型目录...
```

**排查步骤：**

**步骤 1：检查模型路径**
```bash
# Windows
dir "C:\ocr-llm\models\PP-OCRv5_server_rec"

# Linux
ls -la /opt/ocr-llm/models/PP-OCRv5_server_rec
```

**步骤 2：验证模型文件**
模型目录应包含：
- `inference.pdmodel`
- `inference.pdiparams`
- `inference.pdiparams.info`（可选）

**步骤 3：修正配置路径**
```json
{
  "models": {
    "text_recognition": {
      "name": "PP-OCRv5_server_rec",
      "path": "C:/ocr-llm/models/PP-OCRv5_server_rec"  // 使用绝对路径
    }
  }
}
```

## 💻 运行问题

### 问题 7：程序卡住不动

**现象：** 程序启动后长时间无响应

**可能原因和解决方案：**

**原因 1：首次加载模型**
- 等待 2-5 分钟
- 模型加载完成后会继续

**原因 2：Ollama 无响应**
```bash
# 重启 Ollama
# Windows: 任务管理器结束 ollama 进程，重新启动
# Linux:
pkill ollama
ollama serve
```

**原因 3：GPU 内存不足**
```bash
# 查看 GPU 使用情况
nvidia-smi

# 关闭其他占用 GPU 的程序
# 或改用 CPU 模式
```

---

### 问题 8：CUDA out of memory

**错误信息：**
```
RuntimeError: CUDA out of memory
```

**解决方案：**

**方法 1：关闭其他 GPU 程序**
```bash
nvidia-smi
# 查看占用 GPU 的进程，关闭不必要的程序
```

**方法 2：改用 CPU**
```json
{
  "device": "cpu"
}
```

**方法 3：使用更小的模型**
```json
{
  "ollama": {
    "model": "qwen2.5:7b"
  }
}
```

---

### 问题 9：CUDA not available

**错误信息：**
```
RuntimeError: CUDA not available
```

**排查步骤：**

**步骤 1：检查 NVIDIA 驱动**
```bash
nvidia-smi
```

**步骤 2：检查 CUDA 安装**
```bash
nvcc --version
```

**步骤 3：重新安装 GPU 版 PaddlePaddle**
```bash
pip uninstall paddlepaddle paddlepaddle-gpu
pip install paddlepaddle-gpu==3.1.1 -i https://www.paddlepaddle.org.cn/packages/stable/cu129/
```

**步骤 4：改用 CPU 模式**
```json
{
  "device": "cpu"
}
```

---

### 问题 10：内存不足

**错误信息：**
```
MemoryError: Unable to allocate memory
```

**解决方案：**

**方法 1：关闭其他程序**
- 释放系统内存

**方法 2：分批处理**
- 每批处理 50-100 张图片

**方法 3：增加虚拟内存**
- Windows: 系统设置 → 高级系统设置 → 性能 → 虚拟内存

## 🔍 识别问题

### 问题 11：OCR 识别失败

**错误信息：**
```
处理失败: xxx.jpg
  错误: OCR recognition failed
```

**排查步骤：**

**步骤 1：检查图片**
- 图片是否损坏
- 格式是否支持
- 文件是否可读

**步骤 2：检查图片质量**
- 分辨率是否足够（建议 300 DPI+）
- 是否清晰
- 是否过暗或过亮

**步骤 3：手动测试**
```python
from paddleocr import PaddleOCR
ocr = PaddleOCR()
result = ocr.ocr('test.jpg')
print(result)
```

---

### 问题 12：LLM 提取失败

**错误信息：**
```
LLM extraction failed after 3 attempts
```

**排查步骤：**

**步骤 1：检查 OCR 结果**
- 查看 `result/{图片名}.json`
- 确认 OCR 是否识别到文字

**步骤 2：检查 Ollama 服务**
```bash
curl http://localhost:11434/api/tags
```

**步骤 3：手动测试 LLM**
```bash
ollama run deepseek-r1:32b "你好"
```

**步骤 4：增加重试次数**
```json
{
  "ollama": {
    "max_retries": 5,
    "retry_delay_seconds": 2.0
  }
}
```

---

### 问题 13：识别结果不准确

**现象：** 提取的字段值错误

**排查步骤：**

**步骤 1：检查 OCR 结果**
```bash
# 查看 JSON 文件
cat result/0001.json
```

**步骤 2：检查图片质量**
- 提高扫描分辨率
- 确保文字清晰

**步骤 3：调整模板规则**
编辑 `templates/*.json`：
```json
{
  "prompt": {
    "rules": [
      "添加更具体的提取规则",
      "说明特殊情况的处理方式"
    ]
  }
}
```

**步骤 4：使用更强大的模型**
```json
{
  "ollama": {
    "model": "deepseek-r1:32b"
  }
}
```

## 📊 输出问题

### 问题 14：Excel 文件无法打开

**错误信息：**
```
Excel 无法打开文件，因为文件格式或扩展名无效
```

**解决方案：**

**步骤 1：检查文件是否被占用**
- 关闭已打开的 Excel 文件

**步骤 2：删除并重新生成**
```bash
rm output.xlsx
# 重新运行程序
```

**步骤 3：检查磁盘空间**
```bash
# Windows
dir

# Linux
df -h
```

---

### 问题 15：Excel 中数据格式错误

**现象：** 日期变成数字，身份证号变成科学计数法

**解决方案：**

修改模板配置：
```json
{
  "output": {
    "text_columns": [
      "出生日期",
      "登记日期",
      "证件号码",
      "身份证号"
    ]
  }
}
```

---

### 问题 16：输出的 Excel 是空的

**原因：** 所有图片处理失败

**排查步骤：**

**步骤 1：查看控制台输出**
- 检查错误信息

**步骤 2：检查 result 目录**
```bash
ls result/
```

**步骤 3：查看 JSON 文件**
```bash
cat result/0001.json
```

**步骤 4：测试单张图片**
- 选择一张图片单独处理
- 查看详细错误信息
